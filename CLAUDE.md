# Warsaw Downtown — engineering memory

Browser FFA shooter (2–6 players) set in a fictional near-future Warsaw. Product owner: Kiran. Brief: `docs/BRIEF.md` (full) / `docs/DESIGN.md` (condensed). Architecture: `docs/ARCHITECTURE.md`.

## Commands

- `pnpm dev` — client (Vite :5173) + server (Colyseus :2567, `/health`)
- `pnpm check` — typecheck (`tsc -b`) → lint → format:check → vitest → `test:assets` (pytest over `tools/assets/test_*.py`; skipped with a warning locally if Python/Pillow/numpy/pytest is missing, required on CI). Must be green before any commit.
- `pnpm e2e` — Playwright (starts both servers itself; screenshots to `e2e/artifacts/`). ~7 min under software WebGL.
- `pnpm perf` — real-GPU frame-time probe (needs `pnpm dev` running; `WD_MAP=range` for the old street). Reference numbers below.
- `node tools/fps-probe.mjs` — the fps gate on the Market: Low / Medium / High / Auto × three views, fps + p95/p99, draw calls, triangles, internal scale; Intel iGPU by default, `--dgpu` for the NVIDIA; `--quality= --hide=prefix --eval=js --scale= --w= --h= --json=`. Quiet machine only.
- `node tools/fps-bisect.mjs` — where the frame goes: one page with vsync off, uncapped frame time with each mesh group hidden and a few switches (shadows off, shadow filter, empty shadow pass, viewmodel, half resolution), each cut against its own fresh baseline (the iGPU drifts). `--quality= --view=alley|stalls|forecourt --only=group,… --dgpu`.
- `pnpm host` — host for friends from this laptop, no account: build, production server on :2600, Cloudflare quick tunnel, prints the public link (see `docs/HOSTING.md`). Ctrl+C stops it.
- `node tools/feature-sweep.mjs` — real-GPU feature sweep: plays every feature through the autotest hooks and asserts game state, programs stable (no mid-game links), no hitches, NaN 0. Needs a client (`WD_URL`, default :5195) and, for the online part, `GAME_PORT=2625` server (`WD_SERVER`). Flags `--offline`, `--online-only`, `--basic`, `--igpu`, `--only=<substring>` (setup steps still run). Run it after adding or changing features.
- `pnpm soak` — netcode soak / fairness harness: 6 headless clients (the browser's `OnlineSession` + shared sim, one worker thread each) play over real Colyseus sockets against a forked server through a latency proxy; reports hit-confirm rate, false hits, mispredictions, snapshot/tick timing, rewind vs cap; exits 1 on failed thresholds. Flags `--clients --latency <one-way ms, 50> --jitter --loss <%> --seconds <60> --full (10 min match) --quick --bots --server host:port --virtual (no sockets, virtual clock) --json`. Wall-clock runs are distorted by a loaded host (check `frame gaps`); `--virtual` is not. See ARCHITECTURE › Soak and fairness harness.
- `node tools/osm/build-map.ts` — regenerate the Plac Defilad base layer from OSM (see `tools/osm/README.md`).
- `pnpm bake` — re-bake the Market lightmaps (sky occlusion, ~1 min; see `tools/bake/README.md`). Needed after Market geometry changes (a layout change fails a test; an occluder-only change just warns). **Only the lead re-bakes, on `main`, after merging** — lanes never commit re-baked PNGs/manifest.
- `pnpm bots:measure` — bot difficulty measurement (headless, ~2 min on 8 workers): seeded duels (close/mid/long × cold/hot, 200 each per difficulty; spawn protection off: mid-fight encounters) and 1 + 5 FFA matches on the Market (protection on), real `MatchSim` + behaviour tree vs a scripted average-human reference player; prints win rate, reaction, accuracy, headshot share, TTK, spawn deaths with 95 % CIs. `--duels N --ffa M --difficulty d --workers W --json out.json`. Re-run after touching bot aim/fire code or `BOT.difficulty`.
- `pnpm assets:pack` — meshopt-pack every model under `public/models` (run after any model build; a test fails on unpacked models; Python asset tools read shipped meshes through `tools/assets/raw_models.py`, which decodes on demand).
- `pnpm build` — static client + bundled server
- `pnpm format` — prettier write
- Client URL flags: `?autotest` (scripted input via `window.__wd`, no pointer lock), `&governor` (keep dynamic resolution on under autotest).

## Map

- `packages/shared` — pure sim, constants, message schemas, Rapier physics. Runs on client AND server. **Consumed as TS source** (no build step).
  - `src/config/tunables.ts` — every balance number. The only place to tweak feel.
  - `src/sim/` movement, weapon (rifle + semi-auto sidearm), arsenal (slots, switching, knife, grenade throw), grenade (flight + blast), melee, damage, hitbox, hitscan, player, dummies · `src/physics/world.ts` Rapier world + character · `src/maps/`: builder, `geom` (convex polygon toolkit), `solids` (tiers/carving/underground/stairs), `props`, `spawns` (deterministic generation), `concealment` (bush/grass sight model), `registry` (map ids + sizes), `placDefilad/` (the real map), `testStreet` (range).
- `packages/server` — Colyseus 0.18 (`@colyseus/core` + `@colyseus/ws-transport`, **not** the `colyseus` meta-package). `src/app.ts` builds the server; `src/main.ts` listens. `rooms/MatchRoom.ts` (online match) wraps `match/MatchSim.ts` (the authoritative sim incl. combat, testable without sockets; `match/lagComp.ts` pose history + rewind); `rooms/DevRoom.ts` is the M0 ping.
  - Shared netcode: `shared/src/net/` — `protocol` (schemas, `MATCH_NET`), `snapshot`, `reconcile`, `rateLimit`. Client: `client/src/net/` — `onlineSession` (prediction/reconcile/interp bookkeeping, combat events, view time), `interpolation`, `connectOnline` (+ `OnlineJoin`: join at Play, name updates), `combatFeed` (kill feed / score texts), `onlineBadge`; `render/remotePlayersView.ts`.
- `packages/client` — Vite + three.js. `game/Game.ts` (loop, feel, shots) · `input/` · `render/` (map, materials, sky, weather, rain, post, dynamic resolution, viewmodel, effects) · `hud/` · `audio/` · `ui/Menu.ts` · `settings/`. No game rules.
- `tools/` — `perf-probe.mjs`; asset pipeline (bpy, gltf-transform, OSM) from M2.
- `e2e/` — Playwright: `smoke`, `m1`, `arsenal`, `settings` (functional, Low quality), `weather` (visual, High quality). Full suite ~12 min; use `__wd.tap()` (latched) for presses, never hold+sleep.

## Conventions

- Game rules are pure functions in `shared`: `(state, input, dt) → { state, events }`. Rendering code never decides outcomes.
- Every client→server message is validated with a valibot schema from `shared/src/net/protocol.ts`, passed to `room.onMessage(type, schema, cb)`. Invalid payloads never reach game logic (see `server/src/app.test.ts`).
- TS strict + `noUncheckedIndexedAccess`; explicit `.ts` import extensions; `import type` for types.
- Presentation (sky, weather, post, camera feel) never feeds back into the sim.
- Functional e2e runs at Low quality; only screenshot specs use High (software WebGL is ~4 fps at High).
- Conventional commits via `/commit`. Log gate failures to `../loops/FAILURES.md`.
- Every third-party asset goes in `ASSETS.md` before it is committed. CC0 by default; **ask Kiran before any Mixamo asset** and before any paid generation (Grok etc.).
- **One input path for everyone (M6 constraint):** humans and bots both drive players only through `PlayerInput` → `sanitizeInput` → `stepPlayer`. Never add a bot-only shortcut (teleport, direct state writes, extra perception) to the sim or server.
- Nothing TypeSafe/Jev-related is installed or integrated before M6.

## Reference performance

**This laptop has two GPUs: Intel UHD 0x9BC4 and an NVIDIA Quadro T2000 Max-Q.** Chrome picks the Intel one by default (it ignores `powerPreference`). On the T2000 (probes with `WD_DGPU=1` → `--force_high_performance_gpu`; 2026-09-29, Market, 1280×720): Low/Medium/High all 60 fps locked, p95 16.7 ms; motion probe at High: 0 hitches, max 16.8 ms. For players: Windows Settings › System › Display › Graphics › the browser → High performance. The numbers below are the Intel iGPU; since ~2026-09-28 Kiran's real Chrome measured ~22 fps on Low with two displays attached (it was 54–57).

### Intel UHD 0x9BC4, Market, 1600×900, sunny, headless (2026-09-30, `tools/fps-probe.mjs`)

- Low 100 %: 45–49 fps · Medium: 27–30 · High: 20–23 · **Auto: 60 fps, but it settles at Low with 60–65 % internal resolution**. 259–350 draw calls, 0.8–1.3 M triangles.
- Where the Low frame goes (`tools/fps-bisect.mjs`, vsync off, ~21–24 ms): shadows fully off → ~4 ms; an empty shadow pass (no casters) saves only ~5 ms; skipping the shadow _lookup_ saves ~0; half resolution → ~9 ms. Hiding heroes/trees/facades/props/foliage saves ≤ 2–3 ms each; the viewmodel 2–3 ms. So the cost is in the shadow-enabled programs themselves, not the taps or the triangles. The Low/Medium budget 1-tap path (`renderBudget.ts`) saves nothing on D3D11: FXC flattens the branch around the gradient `texture()` compares; `textureLod(…, 0.0)` compares keep the branch (~24 → ~21 ms, branch `lane/igpu-shadows`, parked: not reviewed or cross-browser tested). Next suspects: register pressure / occupancy of the shadow-enabled shader, shadow varyings, the per-light loop.

## Known issues

- Third-person pistol and knife use the rifle hold (no one-hand clips): the support hand stays up where the handguard would be (the pistol reload starts and ends there too).
- Third-person actions: the source clips come without a weapon, so the rifle-grip retarget is approximate (the support hand is clamped to ≤ 8 cm above the bore; the Meshy reloads' gun roll is scaled down by `turn`); the throw and strike arms are plain retargets (a little stiff); a combo's next strike restarts its clip without a blend; no stance-specific throw (the crouch throw clip is used for every stance, upper body only); UAL `Roll` is unused (no dodge in the sim). The sparring partner keeps its tuned procedural knife overlay (only its flinch is new).

- Server cold start via tsx takes ~10 s on first run (Playwright waits on `/health`).
- `msgpackr-extract` native build is ignored, so Colyseus uses its pure-JS msgpack path (fine at our scale).
- The guns' block (F) still raises the primitive guard forearm (the knife's own left arm does it with the knife out).
- FP clips are tuned by eye from scrubbed frames (`tools/_fpanim.mjs`, local): hand orientations on the magazine/bolt are approximate (no finger re-curl: the fingers keep the grip pose), the pistol magazine is small on screen, the shotgun loads shells into the port without a separate loading-gate part, and the dropped magazine falls in gun space (it follows the view for its 0.7 s). Inspect is local only (not seen by others).
- `models/arms` is 0.73 MB of its 1 MB budget (2026-10-02: the atlas re-encoded from the TGA sources by the full `build_fparms.py` package step, 245→175 KB / 493→260 KB at the same `match_jpeg=88` rule, then the knife pose added).
- Sparring partner's knife hand keeps the clip's rifle-grip wrist/fingers (only upper arm + forearm are overlaid); seen straight on, the resting knife is foreshortened and reads mostly by its tip. Authored knife clips (idle/chamber/slash/guard) would replace the overlay.
- Market polish leftovers (graded against the CoD Mobile bar, `docs/polish/AUDIT.md`: ~5/10 High, ~4.7 Low after lane polish): the tall grass's far LOD (> ~32 m from its chunk) is the bare domed core (up close, rim and skirt blades hide it since 2026-10-14); the contact line can read up to ~1.5 cm too near in rare texels where byte rounding shifts a line between the encoder's probes, and reads lighter (never darker) where more than two lines matter in one texel (two corners, a slab's end, an acute tip); the hedge's own core still shows its 30-segment facets on the crown edge; the Palace window field still reads as a fairly uniform grid at 80–200 m (its silhouette was done 2026-10-13: attics, pinnacles, clock, spire); lighting is golden hour by default; dressing (bags, bins) placed flush against a burnt car's collision box clips into the larger car model (decor drives collision: out of a presentation lane's scope).
- Rain leftovers (lane rain, graded against the CoD Mobile bar: clearly better, not there yet): on Low covered surfaces read wet and puddles don't ripple (frame budget); no drips/streams off roof edges and no lens drops; the occlusion is a column test (wind-driven rain never reaches under an awning edge, a tilted plate shelters up to its top edge); tree crowns don't shelter; the rain HDRI's bright patch reflects in puddles as a hot spot on Medium+ (pre-existing at roughness 0.05, now 0.11).
- WebP lossy is always 4:2:0; the hero/atlas normal maps were 4:4:4 JPEGs. Mean angle error of the transcode is 0.4–3° (atlas normal 2.0°), no banding visible in the before/after shots, but a rebuild from source (`match_jpeg`) is the cleaner path if a normal map ever shows chroma bleed.
- Props trucks break (`VEHICLE_IMPACT`, server `match/props.ts`, client `net/propSync.ts`): the baked lightmap/AO under a prop stays where the map put it (a moved crate leaves its contact shadow behind, the new spot has none); bots' walk and drive graphs re-check the ground under each change a few spots per tick (a burst of smashed cartons takes a moment to reach them); a tumbling prop blocks nothing until it settles (≤ `maxTumble`, usually < 2 s), and one at rest round a player stays non-solid until they step out (gone after 3 s more); the greybox fallback (prop models failed to load) keeps drawing props a truck moved where they stood (their collision is right). A prop that settles (or is knocked by someone else) in a driver's path meets the server's truck before that driver's client hears of it: one correction (a contested hit, rare).

## Decisions (why)

- **TypeScript 6.0, not 7.0** — typescript-eslint supports `<6.1`; type-aware lint (no-floating-promises) matters for netcode.
- **Rapier in `shared`**, not client-only — server authority + client prediction need identical collision.
- **60 Hz fixed sim, 30 Hz snapshots** — 30 Hz stepping feels coarse for movement; network rate ≠ sim rate.
- **Own step-up + horizontal-then-vertical move passes** instead of Rapier autostep: autostep fails below ~0.04 m/step, and a combined sweep hitches on flat ground.
- **`@colyseus/core` + `@colyseus/ws-transport` directly** — the `colyseus` meta-package's optional peers made pnpm install two core copies; the room registry split and every join failed with "seat reservation expired". `app.test.ts` guards the real join path.
- **Server port from `GAME_PORT`, not `PORT`** — preview launchers/PaaS shells set `PORT` for the web client.
- **Mouse look at render rate** (raw `pointerrawupdate`, `unadjustedMovement`); the sim samples the view each step; taps are latched. Sensitivity uses Source units (0.022°/count); FOV is horizontal at 16:9 (Hor+); ADS sensitivity is FOV-matched.
- **Rendering: WebGL2 + pmndrs `postprocessing` (Zlib) + N8AO (ISC)**; AgX tone mapping in the post chain; exposure is baked into light/sky intensities so every quality path matches.
- **Procedural PBR textures and synthesized audio** in M1: zero downloads, nothing to license; replaced by real assets in M4/M5.
- **Dynamic resolution first, quality tiers second** (Auto): integrated GPUs are fill-rate bound.
- **Weather is presentation-only and host-chosen online**; the server freezes and broadcasts it with the match settings, so clients share the same presentation and cannot choose a clearer local preset.
- **Default lighting = Golden hour (Kiran, 2026-10-13)** (`WEATHER_PRESETS.golden`, the default in settings, `MATCH_WEATHERS` and quick join; ids appended, old ones stay valid): procedural sky, sun 18° from the south-east (azimuth 135) so it clears the Market's open side and lights the Palace's east face (from the west, 250°, the Palace shaded the whole Market), warm key + cool sky fill so shade reads blue-grey. Chosen over sunny/dusk/neon from a 5-preset contact sheet; fps-neutral on the Intel iGPU (interleaved A/B vs sunny, Low and Auto). **Sky retuned 2026-10-14 (Kiran, option A of a live-tuned sheet, `tools/_goldenTune.mjs`):** the fog takes the horizon colour, so the original cream horizon turned distant glass towers into beige slabs, and cream clouds vanished against it (the skyline looked worse than sunny). Now a near-neutral horizon/haze (`#dad6cf`, fog 0.0009), deeper zenith, 0.48 cloud cover with warm lit tops and cool undersides; `weather.test.ts` pins the intent.
- **Impact VFX per surface (lane impact-vfx, 2026-10-13; presentation only):** `render/impactProfile.ts` (one table per `SurfaceKind`), `impactPool.ts` (fixed pools 768 chips / 256 puffs / 512 glow, oldest recycled, no per-hit allocation), `impactSprites.ts` (alpha dust + additive glow billboards), `debris.ts`. Remote world contacts must match the authoritative endpoint within 5 mm. Every effect draws in its first frame. Low halves puffs and spark trails (trails 30 % shorter). Local probes: `tools/_laneShots.mjs`, `tools/_firefps.mjs`.
